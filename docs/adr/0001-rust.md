# ADR-0001: Rust as implementation language

- **Status:** Accepted
- **Date:** 2026-10-04

## Context

`original/tasks` is a ~1200-line bash script. It works for one person but is hard
to test, slow on listing (one `nb` process per command, awk pipelines per file)
and impossible to extend without editing the script itself. The rewrite must
produce a tool other people can install and extend, with a core library, a CLI,
a terminal UI and a plugin API. Candidates were Rust, Go, Python and TypeScript.

## Decision

The rewrite is written in Rust, as a cargo workspace: a core library crate,
adapter crates and a thin CLI binary, with a ratatui TUI as a later consumer.

Reasons, in order of weight:

1. **Single static binary.** `cargo install tasq` or a downloaded binary works
   with no runtime, interpreter or virtualenv. The tool is invoked many times a
   day from shells, editors and agent sessions; startup cost and install friction
   matter.
2. **ratatui.** The planned TUI gets a mature, actively maintained terminal UI
   library with testable rendering (`TestBackend`).
3. **clap ecosystem.** Derive-based argument parsing, generated help, shell
   completions and man pages cover the whole CLI surface with little code.
4. **Strong types for a plugin API.** Store, Source and Launcher are traits (ADR-0003).
   Rust's type system makes those contracts explicit and checked at compile time,
   both for in-process adapters and for the JSON schema derived from the model
   via serde.
5. **Testing story.** Pure functions with injected clocks and fake processes are
   natural, and `cargo-mutants` can measure test quality on the core.

## Consequences

### Positive

- One artifact to ship per platform; no dependency on the user's Python/Node.
- Core logic lives in a library with unit tests; the script's awk-in-bash logic
  becomes typed functions.
- Fast enough that listing never spawns a process (target: under 50 ms on 500 tasks).

### Negative

- **Slower iteration** than bash or Python: compile times, borrow checker,
  more ceremony for small changes. Mitigated by keeping the CLI thin, adapters
  separate, and fast unit tests over pure core code.
- Contributors need Rust. Mitigated by the out-of-process plugin path
  (ADR-0006), which lets scripts in any language extend the tool.
- Binary size and build time are larger than a script's.

## Alternatives considered

- **Go** — also a static binary with good CLI libraries. Weaker TUI options,
  less expressive type system for the trait-based plugin API, and no equivalent
  of serde for a lossless markdown document model.
- **Python** — fastest to iterate, best LLM tooling. Needs an interpreter and
  environment management on every machine; slow startup for a tool run dozens
  of times per hour; weak static guarantees for the plugin contracts.
- **TypeScript** — good ecosystem, but requires Node at runtime or a bundler to
  produce a binary; terminal UI libraries are less mature than ratatui.
- **Keep bash** — not an option for the goals: untestable, single-file, no
  reusable library, no path to a TUI.
